# Fragrach 評価記録規約

Fragrachの評価は、集計値だけでなく再現・監査・失敗分析に必要な情報を一つの実行ディレクトリへ保存する。

## 実行ごとに保存するもの

| ファイル | 内容 |
|---|---|
| `manifest.json` | 実行ID、開始・終了、所要時間、条件、対象範囲、入力ハッシュ、評価器ハッシュ、Git状態、実行環境 |
| `metrics.json` | 全体・部門別・目的別の集計指標 |
| `retrieval.jsonl` | 全質問・全条件の取得順位、スコア、Knowledge Unit、根拠、質問別指標 |
| `failures.jsonl` | R@10未達など、分析対象となる失敗質問の抜粋 |
| `REPORT_ja.md` | 条件の境界、主要結果、解釈、注意事項を含む人間向け記録 |
| `command.txt` | 再実行に使えるコマンド |
| `error.json` | 失敗時の時刻、例外、スタック、実行コマンド。成功時は作らない |

## 必須の比較境界

- Raw、Oracle、Actualを明示的に分ける。
- Oracleで索引へ投入したGold情報を列挙する。
- 質問文や期待回答を索引へ入れた場合は「回答漏洩あり」と表示し、通常比較から除外する。
- ActualではProvider、モデルID、モデルダイジェスト、コンテキスト長、温度、バッチ、キャッシュヒット率を記録する。
- 途中失敗、除外、再試行、Fallbackを成功結果から消さない。
- 同一条件の比較ではコーパス、質問、評価器のSHA-256一致を確認する。

## 検索評価で残す指標

- 根拠再現率 R@5、R@10、R@20
- 完全取得率 C@5、C@10、C@20
- 根拠適合率 P@5、P@10、P@20
- 文書関係の両端へ到達した Relation Path@5、@10、@20
- Conflict両側の取得率
- Conflict Knowledge Unit取得率
- 正式・現行文書を誤情報より上位にできたResolution Accuracyと、その評価可能範囲
- 誤誘導文書率
- 部門、業種、利用目的、関係種別、質問タグ別の内訳

R/C/Pは同じGold根拠に対して計算する。R@kは必要なGold根拠のうち上位k件で取得できた割合を質問ごとに求め、その平均を取る。C@kは必要なGold根拠をすべて取得できた質問の割合である。P@kは、上位k件のうち未取得のGold根拠を新たに一つ以上追加した検索Unitの割合とする。同じGold根拠を繰り返すUnitはPの分子へ重ねて数えない。一つのDossierが複数のGold根拠を含む場合も、有効な一Unitとして数える。

検索Unitがk件未満の場合、P@kの分母には実際に返された件数を使う。必要なGold根拠があるのに検索結果が0件ならPは0、Gold根拠を定義していない質問はPの集計対象外とする。これにより、Rは取りこぼし、Cは回答に必要な根拠一式が揃ったか、Pは重複を除いた上位候補の密度を表す。

## 回答評価で追加する記録

- 回答要素再現率、禁止誤答率、引用再現率、Strict Pass
- Compile、Retrieve、Assemble、Generate、Cite、Guard、Judgeのどの段階で失敗したか
- 回答モデルへ渡したEvidence Dossierと構造化Answer Contract
- 入出力トークン、待ち時間、再試行、モデル応答の検証結果

## 現在の保存先

企業部門コーパスのOracle検索評価は `target/benchmarks/enterprise-domain-oracle/<run-id>/` に保存する。`latest-run.txt` は直近実行IDを指す。Git管理する文書には主要結果と実行IDを転記し、生の全質問記録は実行ディレクトリに保持する。
